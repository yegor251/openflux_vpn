| Источник | **наш план** (PLAN.md M5: «компромисс VPS = все ключи и куки в одном месте», принято как факт без плана) + **наш опыт**: unpublish 405 (инцидент 2026-10-19, репорт юзера) |

## Проблема

На VPS лежит всё: ключи всех каналов, куки Яндекса, токен бота.
План действий при инциденте (утечка ссылки юзера, взлом VPS, утечка
токена бота, отзыв куков Яндексом) не написан. В момент инцидента
думать с нуля — потеря времени и ошибки.

## Ожидаемый результат

- [ ] playbook по сценариям: утечка одной ссылки (rotate канала,
      сообщение юзеру), взлом VPS (полная ротация: все ключи, куки,
      токен бота, ssh-ключи; порядок шагов, что сначала), утечка
      токена бота (revoke через BotFather, новый токен, рестарт);
- [ ] для каждого сценария — целевое время (например, полная ротация
      VPS ≤ 1 часа) и кто что делает (админ + агент);
- [ ] путь экстренной массовой ротации существует и не требует
      ручного SSH к каждому каналу;
- [ ] playbook отрепетирован на selftest-сервере (не на боевом);
- [ ] ссылка на playbook — из CLAUDE.md (агент знает, где искать).
