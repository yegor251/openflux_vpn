## Общая инфраструктура (что должно быть на месте до тестов)

- **Ношение:** JS-транспорт = подписанный `.flux` (ключ OpenFluxTeam),
  каталог в приложениях (вкладка Transports), обновляется без релизов
  ядра. Node исполняет их скриптовым хостом с 0.15.0; `--native-scripts`
  / `NativeScripts` в node.conf — нативный фолбэк, если пакет не
  подгружен. `wire` в манифесте = поколение формата: клиент и нода
  должны быть на одном wire.
- **Анонимность видна в манифесте:** поле `auth`. У всех пяти
  кандидатов ниже `auth: null` — аккаунт не нужен по декларации.
- **Где смотреть при отладке:** `--inspect-script` (показывает auth и
  cookie jar), журнал `[Telemost]`-подобных тегов, `scripttest` из SDK.

## 1. cupsonline — база самая полная

- **Носитель:** interview-комнаты `https://interview.cups.online/live-coding/`
  (общий редактор; туннель едет в позициях курсора).
- **Создание:** exit создаёт N комнат сам (клиент никогда): POST к
  сервису с **гостевой сессией** — cookie `csrftoken` выдаётся без
  логина; сервис отвечает `roomUUID`/`userUUID` + метой Centrifuge
  (`connURL`, `subURL`, токены). Подписка: POST c `X-CSRFToken` на
  канал `$shared_editor:room-<uuid>`; далее WS Centrifuge.
- **Куки:** только анонимный jar сессии комнаты (никаких аккаунтов).
- **Версии:** JS 1.3.0 (несколько комнат сразу — путь к скорости);
  в ядре 0.15.1 починено зависание лейнов после простоя (наш класс).
- **Живой тест:** создание комнат с нашего VDS (не в бане?), goodput
  1 vs 3 комнат, поведение при закрытии комнат (пере-создание), сутки
  idle → трафик вернулся сам?

## 2. avito (нативный транспорт ядра)

- **Носитель:** `https://code.avito.ru` — документы/комнаты, туннель в
  курсорах; **только этот хост**, кастомный User-Agent (починка #199:
  браузерный UA обязателен, иначе 403).
- **Создание:** REST-создание комнаты + обязательный Socket.IO `join`
  (иначе комната «не существует в MongoDB» навсегда — починено
  0.14.5: транспорт сам делает join при первом ответе «unknown»).
- **Лимиты (дисциплина dialgate.go):** 10 handshake/мин на IP; burst 4,
  далее 1/12 c; пауза после 429 хостовая (файл в temp), растёт до
  30 мин. Несколько нод на одном IP делят бюджет.
- **Куки:** анонимный jar сессии (аккаунт не декларирован).
- **Живой тест:** создание комнат с нашего VDS (429-поведение),
  goodput, сутки idle.

## 3. telemost — база из нашего PoC (TR-08/стенд жив)

- **Носитель:** SFU видеоконференции (join гостевой, без кук); создание
  конференции — POST `cloud-api.yandex.ru/telemost_front/v2/telemost/…`
  **с Yandex-авторизацией** (наша док-сессия даёт 401; создание руками
  в браузере админа — рабочий путь).
- **Блокер:** Session-handshake не сходился на `eee2244`; на продовом
  `12c278e` не перепроверен, а 0.15.0 добавил media API для
  конференц-носителей (VP8/VP9/H264 треки) — пере-PoC обязателен.
- **Живой тест:** тот же стенд (override на ноде + клиент), замер
  goodput, смерть конференции = честная смерть туннеля?

## 4. pruffme / mtslink / bitrix — малоизученные (JS, trader52)

| транспорт | эндпоинт | auth | что известно |
|---|---|---|---|
| pruffme 1.0.0 | `pruffme.com/landing/u` | null | российская вебинар-платформа; «no cells left on the board» (анти-детект) |
| mtslink 1.0.0 | `my.mts-link.ru` | null | МТС Link (Вебинар); `my.` намекает на дашборд — проверять анонимность комнат |
| bitrix 1.0.0 | `boards-ruv.i.bitrix24.ru` | null | публичные доски Bitrix24 (регион ru) |

- **Механика у всех:** курсорные обновления на белой доске, stripe-обёртка
  ядра. Манифесты анонимны; сервисные лимиты/капчи не задокументированы.
- **Риски:** российские сервисы, нагрузка на бесплатный тариф, устойчивость
  ссылок. База исследовательской этики: не спамить, один тестовый канал.
- **Живой тест:** один канал, сутки, замеры; сервис с капчей — сразу мимо.

## Чек-лист любого живого теста (15–40 мин на транспорт)

1. Каталог/манифест: `auth` по-прежнему null? версия?
2. Нода: `[Transport <id>]`-секция или `.flux` в `NativeScripts`; журнал
   — комнаты/лейны поднялись?
3. Клиент (socks5-стенд): handshake → curl goodput (методика CORE-06).
4. Idle-тест: 30+ мин тишины → трафик вернулся сам?
5. Смерть носителя (комнату закрыть/конференцию убить) → туннель умер
   честно, клиент реконнектится?
6. Вердикт в этот файл: таблица «дата / билд ядра / goodput / соуп».
