## Проблема

В ядре появился транспорт, где туннель едет видеоконференцией Яндекс
Telemost: SFU релеит RTP-стримы, ядро кладёт поверх свой in-order
ARQ. Апстрим меряет 4.4–5 MB/s стабильно. Это **маскировка под
видеозвонок** — ровно та ниша, которую у нас освободили яндекс-доки
(TR-01), но без куков и капчи: конференция живёт по ссылке.
Ограничения апстрима: одна конференция = один клиент+exit; desktop
full-tunnel пока отказывается (риск media-loop), мобильные клиенты
через VPN-интерфейс — ок.

## Ожидаемый результат

- [ ] PoC-канал telemost на тест-VDS: выпуск, подключение CLI-клиента
      с tun, замер goodput/латентности нашей методикой (CORE-06);
- [ ] суточный soak: стабильность лейнов, поведение при потере
      конференции (ссылка умерла) — туннель должен честно умирать,
      а не зависать (CORE-02);
- [ ] проверены мобильные клиенты (Android как минимум): media-loop
      не возникает, full-tunnel работает;
- [ ] verdict-документ: кандидат ли Telemost на роль «маскировочного
      лейна» вместо док-носителей, ограничения (одна конференция =
      один клиент — совместимо ли с нашей моделью «канал = юзер»);
- [ ] если да — план включения в выпуск каналов (oflux-admin/bot),
      если нет — причины и что должно измениться.
