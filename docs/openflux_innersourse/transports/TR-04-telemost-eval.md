# TR-04 — Оценка Telemost как маскировочного лейна

| | |
|---|---|
| Область | транспорты-посредники |
| Приоритет | P1 |
| Статус | **оценён 2026-10-23: не готов** — Session-handshake через telemost не сходится даже между пирами одного билда; класс механизма подтверждён и перспективен, вернуться после апстрим-фикса |
| Зависимости | CORE-02; следующий иннерсорс-шаг: репорт блокера в апстрим |
| Апстрим | Telemost-транспорт (0.5.0+); линия OpenFluxTeam 0.14.0 (#195); #190 (iOS NE гибнет) |
| Источник | **наш PoC 2026-10-23** (живые пробы) + исходники ядра + #195 (тело проверено) |

## Проблема

В ядре появился транспорт, где туннель едет видеоконференцией Яндекс
Telemost: SFU релеит RTP-стримы, ядро кладёт поверх свой in-order
ARQ. Апстрим меряет 4.4–5 MB/s стабильно. Это **маскировка под
видеозвонок** — ровно та ниша, которую у нас освободили яндекс-доки
(TR-01), но без куков и капчи: конференция живёт по ссылке.
Ограничения апстрима: одна конференция = один клиент+exit; desktop
full-tunnel пока отказывается (риск media-loop), мобильные клиенты
через VPN-интерфейс — ок.

## Оценка 2026-10-23 (ход, живые проверки)

Факты из исходников и лайв-проб (curl к `cloud-api.yandex.ru`):

| Проверка | Результат |
|---|---|
| Вход в конференцию (JOIN) | **гостевой, без кук**: запрос connection по несуществующей ссылке → `404 ConferenceNotFound` (не 401) — дата-плейн не зависит от свежести кук и не проходит капчи посреди сессии |
| Создание конференции API-ем | **требует авторизации**: без кук 401; с нашей боевой док-сессией тоже 401 («Не авторизован») с VPS и с домашнего IP — cloud-api-аутентификация ≠ док-сессия; авто-создание ядром (пустой URL → POST с Cookie+X-Uid) у нас не работает |
| Конфиг ноды | `node.conf` — INI `[Transport telemost] Type/URL` — секция пишется руками; **инсталлятор telemost-ключа не имеет** (productization = добавить `TELEMOST=` в make_fork при положительном вердикте) |
| Desktop full-tunnel | ядро само отказывается (media-loop guard, `hasTelemost`) — клиенты: socks5-режим или Android VPN |
| iOS | известный убийца: NE гибнет через 4 c (#190) — iOS-юзеров на telemost не сажать до апстрим-фикса |

Смена модели эксплуатации против док-переносчиков: конференция
создаётся **один раз админом в браузере** (30 c под своим аккаунтом),
ссылка зашивается в канал; JOIN обеих сторон без кук. Капча-риск
остаётся только в момент создания руками — то есть на человека, а не
на headless-ноду. Не выяснено (для PoC): время жизни мгновенной
конференции-ссылки, поведение при смерти конференции (честная смерть
туннеля), goodput с нашего VDS, суточный soak.

## Вердикт (2026-10-23): НЕ ГОТОВ для продукта

Полный PoC (конференция от админа, нода l4 на тест-VPS, CLI-клиент
socks5 с домашнего IP, лейн telemost-only, `--negotiate`):

| Проверка | Результат |
|---|---|
| Нода поднимается | ✅ `[Transport telemost]` в node.conf, 3 лейна, SFU Yandex (77.88.43.37 / 5.255.254.50) доступен и с датацентра, и из дома; guest-join без кук |
| Стыковка лейнов | ✅ после вычистки «призраков» клиент видит ровно 3 тега ноды (пары сайт-браузер/мёртвые процессы ломают «новейший ран» — эксплуатационная тонкость) |
| **Session-handshake** | ❌ **блокер**: `N frames arrived, 0 decrypted, 0 hellos` → `handshake timed out`. Воспроизводится: (а) на текущем main+наш PR (`4e27403`, обе стороны), (б) на линии OpenFluxTeam `eee2244` (0.14.0/node-v1.8.1), (в) после 190 c выдержки без призраков. Нода параллельно рапортует «peer sends classic-mode frames» (в 0.14.0 это заявлено как ложная тревога от филлеров 30 fps, #195) и теряет стрип-пьесы (`gave up on N pieces`) |
| Goodput | не измерен — до данных не дошли |

Продуктовые ограничения (независимо от блокера): desktop full-tunnel
отказывается сам (media-loop guard); iOS сломан апстримом (#190);
одна конференция = один клиент+exit; инсталлятор не умеет
telemost-ключ (нужен `TELEMOST=` в make_fork); создание конференции —
вручную в браузере админа (API-создание требует auth ≠ док-сессия,
проверено 401 с двух IP).

**Решение:** direct остаётся единственным лейном. Вернуться к TR-04
после апстрим-фикса handshake (следить за #195 и релизами); стенд
сохранён: конференция жива, `/etc/openflux-node/of-telemost-poc/` +
systemd-override на `openflux-team-eee2244` (для повторной оценки —
только обновить бинари обеих сторон).

**Следующий иннерсорс из этой оценки:** репорт блокера в апстрим
(repro: node.conf `[Transport telemost]` + клиент `--negotiate`,
одинаковый билд на обеих сторонах, логи `[SESSION]`/`[STRIPE]`).
