# TR-03 — Оценка vyandex как посредника

| | |
|---|---|
| Область | транспорты-посредники |
| Приоритет | P2 |
| Статус | open |
| Зависимости | CORE-02 (live-lock не должен маскировать результаты) |
| Апстрим | #160, #161, #176 (SmartCaptcha-петли), #89 (захардкоженный UA → капча, «фикс в одну строку»), #151 (UA Safari vs Firefox) |

## Проблема

vyandex — второй яндексовый транспорт в ядре, мы его никогда не гоняли
(PLAN: «у него свои open issues по капче — не лучше»). Но набор багов
другой: часть выглядит дёшево починенной (#89 — UA, #151 — UA в
CaptchaView), а часть — фундаментальная (#160: mid-session капча
недостижима из мобильного приложения). Прежде чем списывать, нужен
наш собственный вердикт на нашем exit.

## Ожидаемый результат

- [ ] vyandex-канал поднят на тест-VDS (не боевой): verdict-документ с
      логами — работает/не работает, где именно упирается;
- [ ] проверены обе точки: свежий выпуск и длительная сессия
      (mid-session капча из #160);
- [ ] если работает: критерии боевого включения (по аналогии с
      WHY_MASKING) и ограничение «клиенты из RF-сетей?» сняты замером;
- [ ] если нет: список блокеров оформлен в апстрим (или дополнен
      комментарий к существующим #160/#161/#89) с нашими логами.
