# TR-07 — Собственный JS-транспорт на OpenFluxSDK

| | |
|---|---|
| Область | транспорты-посредники |
| Приоритет | P2 |
| Статус | open |
| Зависимости | TR-06 (куда встраивать), осознанное решение «нам нужна своя маскировка» |
| Апстрим | OpenFluxSDK: подписанный JS (.flux) в goja-рантайме, host API (HTTP/WS/UDP/WebRTC/cookies), ed25519-подпись обязательна |

## Проблема

Апстрим дал SDK: транспорт пишется на JS, подписывается ed25519-
ключом и грузится в ядро без пересборки; в приложениях включается
как «экспериментальная функция». Это путь к **собственному**
маскировочному лейну, который не зависит от капризов Mail.ru/Яндекса
(например, WebSocket к своему же релею за CDN, неотличимый от
обычного веб-трафика). Цена: своя инфраструктура релея, подпись и
дистрибуция транспорта нашим пользователям, поддержка в клиентах.

## Ожидаемый результат

- [ ] verdict-документ: покрывает ли SDK наш кейс (host API,
      ограничения рантайма goja, модель подписи — чей ключ, кто

- [ ] прописан минимальный кандидат-транспорт (какой ресурс маскируем,
      где релей, что с латентностью) — без реализации, только
      требования и ожидаемые характеристики;
- [ ] решение принято и зафиксировано: делаем / не делаем, критерии
      пересмотра;
- [ ] если «делаем»: PoC транспорт + релей проходят суточный soak и
      вписываются в бюджет CORE-06, клиенты наших юзеров грузят
      подписанный транспорт без ручных настроек.
