# SRV-02 — Ресурсные лимиты канала (соседи не топят друг друга)

| | |
|---|---|
| Область | exit-ноды |
| Приоритет | P1 |
| Статус | open |
| Зависимости | SRV-01 (реалистичные пороги) |
| Апстрим | открытый пункт M2 в PLAN.md |

## Проблема

Каждый канал — отдельный systemd-юнит, но без лимитов: один жадный
пользователь (торренты, 50 соединений) может съесть CPU/RAM/таблицу
процессов и уронить соседей. Открытый пункт плана M2: drop-in с
MemoryMax/CPUWeight/TasksMax. Важные нюансы: лимиты не должны валить
л3 (CAP_NET_RAW уже в drop-in), а OOM-kill юнита должен быть виден
 watchdog'ом как сбой, а не «тихий» рестарт.

## Ожидаемый результат

- [ ] инсталлятор ставит каждому каналу лимиты (память, CPU-вес,
      задачи); значения из SRV-01, не с потолка;
- [ ] тест «жадный сосед»: канал под максимальной нагрузкой — соседние
      каналы держат goodput и откликаются, узкое место в юните
      жадного, а не в системе;
- [ ] OOM/срабатывание лимита: юнит перезапускается сам, watchdog
      видит NRestarts и шлёт алерт по своим порогам (K/M);
- [ ] лимиты применяются и при rotate/обновлении канала — не
      теряются.
