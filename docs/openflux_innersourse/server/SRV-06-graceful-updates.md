# SRV-06 — Обновления ядра ноды без «внезапной смерти» каналов

| | |
|---|---|
| Область | exit-ноды / эксплуатация |
| Приоритет | P1 |
| Статус | open, ждёт решения A/B от админа |
| Зависимости | CORE-02 (клиент должен выживать рестарт), CORE-03, OPS-03 |
| Апстрим | node-v* релизы каждые 1–3 дня; авто-апдейтер у нас на VPS (таймер 6 ч) |
| Источник | **наш план и наш опыт**: открытая приёмка M5.5 (решение A/B), зомби-рестарты (CORE-01/02); темп релизов — наблюдение по списку релизов апстрима |

## Проблема

Каждое обновление ядра = рестарт всех каналов = зомби-клиенты (до
починки CORE-02/03) и разрывы сессий. Сейчас авто-апдейтер обновляет
в любое время суток. Открытое решение в приёмке M5: **A** =
авто-апдейт выключить (обновляемся руками в окно) или **B** = оставить
с окнами и уведомлением пользователей. Ни то, ни другое не оформлено.

## Ожидаемый результат

- [ ] решение A/B принято админом и записано в PLAN.md;
- [ ] при A: авто-таймер выключен, ручная процедура обновления (проверка
      CORE-06 на новой версии → окно → обновление → уведомление юзерам
      «переподключитесь») описана и отрепетирована;
- [ ] при B: обновления только в ночные окна; бот рассылает
      затронутым пользователям предупреждение до и «можно
      переподключаться» после;
- [ ] в обоих случаях: после обновления подтверждено, что все каналы
      поднялись (probe), зомби-первое-подключение погашено (CORE-01),
      алерт если какой-то юнит не поднялся.
