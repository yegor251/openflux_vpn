## Проблема

Наши точки отсчёта разрозненны: direct+l3 до 4.8 MB/s (замер
2026-10-18, mirror.yandex.ru, 10 MB), l4 = 0.6–4.3 MB/s в зависимости
от времени суток. Замены рукопожатные, разовые, без зафиксированной
методики. Нет способа ответить «стало ли хуже после обновления ноды
с X до Y» кроме субъективных ощущений.

## Ожидаемый результат

- [ ] скрипт-бенчмарк (клиент + нода): goodput, латентность, CPU и RSS
      ноды на фиксированной нагрузке; методика зафиксирована в docs
      (файл, размер, число потоков, время суток не влияет на вывод);
- [ ] таблица результатов по режимам (l3/l4) и по версиям ядра ноды
      ведётся в этом репо;
- [ ] правило принято: обновление ядра ноды, просевшее goodput более
      чем на N% относительно предыдущей версии, откатывается
      (rollback-механизм апдейтера уже есть);
- [ ] измерена память на один активный канал — вход в формулу
      ёмкости из SRV-01.
