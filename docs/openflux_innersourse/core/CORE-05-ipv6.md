| | |
|---|---|
| Область | ядро + нода + клиенты |

| Зависимости | CORE-04 (l3-режим устоялся) |

| Источник | **продуктовая логика**; подталкивается апстримом #161 (тело проверено: WebView уходит в v6, ядро dial-ит v4-first — spravka-куки отвергаются) |

## Проблема

Весь стенд — IPv4: клиентский tun поднимает v4-сеть 10.10.10.x, выход
raw-SNAT в v4. Растущая доля сетей — IPv6-only (LTE-операторы,
публичный Wi-Fi с NAT64). Не определено: умеет ли клиентский стек
работать на v6-only аплинке, отдаёт ли нода v6-выход, нет ли утечек
(v6-трафик мимо туннеля при dual-stack клиенте).

## Ожидаемый результат

- [ ] вердикт: как ведёт себя каждый клиент на v6-only аплинке
      (работает / падает / идёт мимо туннеля) — таблица по платформам;
- [ ] dual-stack клиент: ни один пакет не уходит в интернет вне
      туннеля (проверено тестом на утечку v6);
- [ ] нода: либо отдаёт v6-выход (SNAT v6), либо явно задокументировано
      «v6-цели недостижимы» и клиенты не ломаются на этом;
- [ ] vyandex-транспорт (если вернём, TR-03) не ловит #161 на
      v6-клиентах — проверено.
