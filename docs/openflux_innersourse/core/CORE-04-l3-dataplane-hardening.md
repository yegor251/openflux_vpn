## Проблема

l3 — наш боевой режим (direct, raw-SNAT). Известные шероховатости:
conntrack — userspace-карта с потолком 65536 записей (Insert фейлится
на полном/остановленном состоянии, поведение при переполнении не
определено операционно); дроп-счётчики `[L3-STATS]` видны только с
`Debug = 2` вручную; kernel-RST правило обязано стоять первой строкой
OUTPUT под ufw — инвариант держится на честном слове инсталлятора.
Класс `drops: noct` (нет conntrack-записи) не имеет playbook'а.

## Ожидаемый результат

- [ ] каждый класс дропов (bad/fragmented/notus/nokey/noct) имеет
      задокументированную причину и что делать дежурному;
- [ ] поведение conntrack при исчерпании определено: что происходит
      с новыми потоками и как это видно снаружи (метрика/алерт);
- [ ] self-check скрипт/юнит: проверяет порядок firewall-правил,
      forwarding и raw-сокеты после загрузки и по таймеру, при
      расхождении — алерт админу;
- [ ] суточный soak на боевом VDS: ноль «тихих» дропов при штатном
      трафике, счётчики сходятся (fromTr = toCli + drops).
