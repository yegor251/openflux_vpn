# Innersource-бэклог: работа в репозиториях OpenFlux

Здесь только задачи, решаемые **в чужих репозиториях** (issue или
форк → ветка → PR): ядро OpenFlux, клиенты (Android/iOS/Desktop),
транспорты апстрима. Всё, что делается внутри нашего сервиса
(oflux-admin, бот, VPS, эксплуатация, безопасность, дистрибуция) —
в соседнем каталоге `docs/openflux_service/`.

**Формат задачи:** один файл = одна задача. Обязательные части:
проблема/контекст (с фактами и ссылками) и ожидаемый результат
(чек-лист приёмки). Решения в файлах нет — выбирается при работе
над задачей.

**Статусы:** `open` → `in-progress` → `done` (правится в шапке файла;
в done — дата и ссылка на коммит). Приоритеты: P0 — блокирует продукт;
P1 — важное; P2 — расширение. Колонка **MVP** — по критериям админа
(удобство клиента, скорость, стабильность): `да` = обязателен до
запуска для посторонних пользователей, `частично` = наш кусок
минимален, `нет` = после запуска.

**Пометка «Источник»** в шапке каждой задачи — честное происхождение:

- «**апстрим-задача**, тело проверено» — выросло из содержания issue
  апстрима; тела прочитаны 2026-10-19;
- «**только заголовок**» — issue упомянут по заголовку, тело не
  читалось; перед работой по нему — прочитать;
- «**репо/CHANGELOG апстрима**» — из документации, README или релизов,
  не из issues;
- «**наш опыт/план**» — наблюдения эксплуатации и пункты PLAN.md
  этого репозитория;
- «**продуктовая логика**» — авторская задача, внешнего источника нет.

## Как вносить изменения в апстрим

- **Issue — точка входа**, форк не нужен; апстрим реагирует быстро
  (сентябрьско-октябрьские репорты чинились за дни). Наши находки
  (зомби-гонка, live-lock, RST-под-ufw) пока не оформлены — это
  CORE-01/02.
- **PR — из ветки форка** `yegor251/OpenFlux` → `main` апстрима:
  11 из 37 merged PR апстрима сделаны внешними через форки
  ( damnurmum — 7), путь штатный. Формальных правил (CONTRIBUTING.md)
  нет.
- Рабочий клон: `~/PycharmProjects/OpenFlux-contrib` (origin = форк,
  upstream = `p1neappleXpress`); `OpenFlux/` внутри этого репо —
  одноразовый референс, в нём не работать. Пуш по HTTPS через
  osxkeychain; `gh` не установлен — PR через веб.
