# Иннерсорс — только необходимое

**Куда постить:** баги ядра → issue в `p1neappleXpress/OpenFlux` (код —
PR из ветки форка `yegor251/OpenFlux`); клиентское — в репо клиентов
(`OpenFluxAndroid` / `OpenFluxDesktop`). Линия `OpenFluxTeam` —
внутренняя кухня команды, не для чужих issue. Прод-ядро собирается из
team-линии (пин по коммиту, см. CLAUDE.md).

## Закрыто (2026-10-23, team-ядро 0.15.x, верифицировано)

Зомби-первое-подключение, live-lock после рестарта ноды, автореконнект —
закрыты **нативно** (exit отвечает hello без handshake, takeover ~4 c;
замеры: 10/10 рестартов без зомби, восстановление клиента t+9 c). Наш
PR #212 остался в апстриме как фикс для пользователей релизной линии.
Детали/логи — git-история этого репо (файлы CORE-01/02/03 удалены при
чистке 2026-10-24).

## Живые задачи

- **TR-08** (`transports/`, «сделаем позже») — репорт Telemost-блокера
  handshake в апстрим; самодостаточен.
- **CL-07** (`clients/`) — статус трафика + кнопка «переподключить» в
  клиентах; подавать после ближайшей клиентской приёмки.

## Задел (не горит, файлов нет)

- Матрица версий: прод-нода = team-линия (пин по SHA); клиенты юзеров —
  только team-сборки 3.10.x (основные репы заморожены на 3.7.0).
- l3-дежурное: классы дропов `[L3-STATS]` и потолок conntrack 65536 —
  playbook (Debug = 2, счётчики fromTr/toNet/fromNet/toCli).
- IPv6: поведение клиентов на v6-only аплинке, тест утечек.
- Формат ссылки v2 (мульти-лейн, TTL) — только через апстрим, кодек
  не форкаем.
- Транспорты yandex/mailru/vyandex — мертвы или неанонимны (sign-in в
  манифестах), не возвращать без внешнего события. Актуальный план
  транспортов — `docs/PLAN.md` → «Новые транспорты».
