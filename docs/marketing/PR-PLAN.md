# PR-план v2: МАССОВЫЙ пиар (бюджет $10, время — много)

Дата: 2026-11-05. Продукт: телеграм-бот, выдающий персональные VPN-каналы
на носителях (telemost / cupsonline) поверх OpenFlux.

Допущение админа (2026-11-05): массовое продвижение ведётся осознанно;
риски законодательства о рекламе в РФ приняты и в план не возвращаем.
Документ исходит из этого допущения.

## Главный конфликт: трафик против ёмкости

Сейчас: 1 VDS, port_range 20000-20099, max_channels 20, оба носителя
на одном IP. Массовый пиар без подготовки = день трафика, минута славы,
потом «сервер переполнен», чаты заминусили продукт, reputation burnt.

Поэтому план начинается с ёмкости, а не с публикаций.

## Шаг 0 (неделя 0): подготовить приём

1. **Второй VDS** ($5-6/мес — вот куда идёт бюджет $10: это первый
   месяц второго сервера). Тот же node-install.sh ставится одной
   командой; проверить поддержку второго сервера в servers.yaml бота
   (список там есть; если бот умеет только первый сервер — это
   маленькая доработка в `oflux_admin`, до пиара успеваем).
   Итого ~40 слотов. Дальше каждый новый VDS = +20-40 слотов за $5.
2. **Приёмный контур**: свой TG-канал (название с ключевыми словами
   «VPN / обход блокировок» — поиск внутри Telegram это SEO), описание
   со ссылкой на бота, закреп с инструкцией. Канал = витрина и место
   для контента, бот = продукт.
3. **Лендинг на GitHub Pages** (бесплатно): одна страница — что это,
   как работает (носители), /download, кнопка на бота. SEO по запросам
   «vpn который работает 2026», «обход белых списков» — долгий
   органический хвост.
4. **Реферальный крючок в боте** (маленькая фича): у каждого
   пользователя свой deep-link-инвайт; в аналитику пишем `invite_from`.
   Массовый пиар без встроенной виральности — как ведро с дыркой.

## Контент-волны (недели 1-8), площадка → формат → ожидаемый охват

### Волна 1 — Habr (недели 1-2) «Сделай сам»
Лонгрид-туториал: «Своя VPN-ферма на носителях: OpenFlux + боте за вечер».
Инструкция с нашим стеком, честные цифры (0.85-1.15 MB/s), история
инцидентов. Хабр = инженеры = те, кто поставит себе сам И приведёт
других. Ссылка на GitHub OpenFlux + на свой канал. Это самый
конверсионный формат для технического продукта.

### Волна 2 — Pikabu (недели 2-3) «История»
Пост-история личного опыта (короче и человечнее Хабра): «Как я делал
VPN, который пережил белые списки». Пикабу даёт десятки тысяч просмотров
при попадании на главную — это самый массовый РФ-канал в плане.
Ссылку на бота — в первый коммент/профиль.

### Волна 3 — видео (недели 3-6, параллельно) YouTube + Rutube + Дзен
5-10-минутные туториалы: установка на Android/iOS/Mac по инструкциям
бота. Видео = долгий поисковый трафик (люди ищут «как поставить vpn
2026» на YouTube). Дзен дополнительно подхватывает РФ-выдачу. Это
time-heavy: одно видео ≈ вечер, серия из 4-6 роликов = месяц.

### Волна 4 — TG-экосистема (постоянно с недели 1)
- Комментарии в крупных TG-каналах (под постами про блокировки — там
  тысячи читателей в обсуждениях). Полезные комменты, не спам;
  ссылка на свой канал, не на бот.
- 2-3 десятка тематических чатов: отвечать на вопросы, канал в профиле.
- **Бартер-взаимопиар** с мелкими каналами (1-5k подписчиков) в темах
  приватности/айти: их пост у нас ↔ наш у них. Бесплатно, работает.
- tgstat-каталоги: зарегистрировать канал и бота в каталогах ботов.

### Волна 5 — 4PDA + VC.ru (недели 4-6)
- 4PDA: тема «Суверенный интернет» и раздел VPN — активные треды,

## Метрики

Аналитика бота — воронка целиком:
- `issue` за сутки после каждой публикации = конверсия площадки;
- `invite_from` (после фичи) = виральный коэффициент;
- `revoke` в первые сутки = качество первого впечатления;
- подписчики канала → `issue` = конверсия витрины.
Правило: площадка не дала 5 issue — не повторяем формат.

## Анти-риски (технические, не юридические)

- **Баны за спам**: в чатах — только ответы; в каналах — ссылки на
  витрину, не на бот. Публиковаться с раскаткой (не всё в один день).
- **Качество при росте**: watchdog уже кричит; при > 30 issue/нед —
  сначала ёмкость/третий VDS, потом новая волна.
- **Честность продукта**: не обещать «100% всегда»; у нас были
  переезды носителей — и это нормальный сюжет, а не провал.
- **Слоты кончились**: бот пишет «сервер переполнен» — на пике добавить
  VDS быстрее, чем придёт вторая волна трафика.
