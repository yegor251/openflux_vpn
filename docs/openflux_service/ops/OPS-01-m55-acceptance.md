## Проблема

M5 (бот) принят частично: выпуск/rotate/revoke юзером проверены,
но алерты не проверены ни разу живым тестом, массовый сбой не
симулировался, второй реальный пользователь не заходил. Кроме того,
висит решение A/B по авто-апдейту (SRV-06).

## Как тестировалось

Канареечные каналы `of-canary-1/2` (tg_id 42424201/42424202, созданы
`issue_channel(name_base=...)`) — на них гоняются все отказные тесты,
боевые каналы не трогаются.

## Ожидаемый результат

- [x] живой тест алертов: остановлен юнит канала → 🔴 в личку админа
      после 3 проб (~15 мин), запущен → 🟢 — подтверждено админом
      2026-10-21;
- [x] массовый сбой симулирован: обе канарки вниз (2 из 4) → ровно
      ОДИН агрегированный 🚨, отдельных 🔴 нет; после подъёма — 🟢
      «прошёл» — подтверждено;
- [x] протухание кук симулировано (ya-cookies.txt спрятан на 16 мин) →
      🟠, файл возвращён → 🟢 — подтверждено; напоминания покрыты
      юнит-тестом (cooldown);
- [ ] второй реальный пользователь зарегистрирован по приглашению и
      работает (частично закрывается PRD-05) — приглашение выдано,
      ждёт юзера;
- [x] решение A/B по авто-апдейту принято: вариант A, см. SRV-06
      (2026-10-20).

## Попутно починено при приёмке

- watchdog держал реестр-снапшот со старта бота → каналы, выпущенные
  позже, были невидимы; теперь реестр перечитывается каждый цикл
  (аналогично BotUsers — приглашения CLI больше не теряются);
- TelegramNetworkError убивал процесс, а недоставленный алерт
  помечался отправленным навсегда; теперь поллинг переживает
  пропадание сети, недоставка откатывает состояние и повторяется
  следующим циклом (тест: два флапа 2026-10-21 15:27/15:33 UTC).
