# SEC-03 — Гигиена ключей: ротация, аудит, запрет навсегда-живых ссылок

| | |
|---|---|
| Область | безопасность / продукт |
| Приоритет | P1 |
| Статус | open |
| Зависимости | PRD-01 (массовые операции), формат ссылки v2 (задел) |

| Источник | **наш опыт**: rotate только руками юзера (нет политики/аудита); unpublish 405 — живой инцидент 2026-10-19 (проверено: метода в models-v2 нет) |

## Проблема

Ключ канала живёт вечно, пока юзер сам не нажмёт `/rotate`. Ссылка =
ключ, лежит в чатах, скриншотах, истории телефона. Нет ни политики
ротации, ни аудита (когда у кого менялся ключ — не ответить),
ни «мягкой» недействительности старых ссылок с понятным сообщением.
Плюс известная дыра уборки: отозванный канал оставляет
опубликованный док-носитель (пока у нас direct-only — пустышка, но
при возврате лейнов — след в Яндексе).

## Ожидаемый результат

- [ ] политика ротации принята: период или триггеры (инцидент, уход
      юзера) — записана; напоминание юзеру/админу о давней ротации;
- [ ] аудит-события (issue/rotate/revoke/invite: tg_id, время, канал)
      пишутся append-only и хранятся ≥ 90 дней; по ним отвечает вопрос
      «когда у канала X менялся ключ»;
- [ ] старая ссылка после rotate не молчит: клиент/бот говорит
      «ключ ротирован» (если формат позволит — задел «формат ссылки v2»; иначе поведение
      задокументировано в FAQ);
- [ ] ограничение yandex-unpublish: либо найден рабочий метод отзыва
      (OAuth?), либо в playbook (OPS-03) есть ручной шаг чистки в вебе.
