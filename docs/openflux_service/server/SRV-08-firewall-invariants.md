## Проблема

l3 жив, пока: kernel-RST правило стоит **первой** строкой OUTPUT
(ufw-цепочки ACCEPT-ят `ctstate NEW` раньше appended-правил),
включён forwarding и oneshot-юнит восстанавливает правило после
ребута. Всё это держится на инсталляторе; ни ufw reload, ни ручные
манипуляции админа, ни обновление самого ufw не проверялись на
разрушение инварианта. Пакетные счётчики мы смотрели руками.

## Ожидаемый результат

- [ ] self-check: скрипт/юнит валидирует порядок правил, счётчики
      RST-правила, forwarding; расхождение = алерт админу (в watchdog
      бота);
- [ ] drills пройдены: reboot, `ufw reload`, `ufw disable/enable` —
      после каждого инвариант восстановлен автоматически (или drill
      показал ручную процедуру, и она задокументирована);
- [ ] при выпуске нового канала и при обновлении ядра ноды инвариант
      перепроверяется автоматически (не только на reboot);
- [ ] чек-лист диагностики «интернета нет, юнит жив» дополнен шагом
      «проверь firewall-инвариант» (CLAUDE.md/FAQ дежурного).
