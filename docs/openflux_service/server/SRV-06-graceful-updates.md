## Проблема

Каждое обновление ядра = рестарт всех каналов = зомби-клиенты (до
починки CORE-02/03) и разрывы сессий. Сейчас авто-апдейтер обновляет
в любое время суток. Открытое решение в приёмке M5: **A** =
авто-апдейт выключить (обновляемся руками в окно) или **B** = оставить
с окнами и уведомлением пользователей. Ни то, ни другое не оформлено.

## Решение (2026-10-20): вариант A

Админ выбрал A: сюрприз-рестарты хуже отставания на версию. Авто-таймер
`openflux-node-update.timer` выключен (`disable --now`), процедура
обновления — в CLAUDE.md («Ядро ноды обновляется ВРУЧНУЮ»).

## Ожидаемый результат

- [x] решение A/B принято админом и записано (здесь + CLAUDE.md);
- [x] при A: авто-таймер выключен (`systemctl is-active
      openflux-node-update.timer` = inactive);
- [x] ручная процедура обновления описана (CLAUDE.md) и отрепетирована:
      ручной `systemctl start openflux-node-update.service` проходит,
      {"updated":false} (новых релизов нет), юниты каналов не
      перезапускались;
- [ ] первый ОБЫСКОВЫЙ апдейт по процедуре (когда выйдет новый node-v*):
      бенчмарк CORE-06 до/после, окно, обновление, уведомление юзеров,
      все юниты active — закрыть при первом реальном релизе.

## Ожидаемый результат (вариант B — не выбран, хронология)

- [ ] при B: обновления только в ночные окна; бот рассылает
      затронутым пользователям предупреждение до и «можно
      переподключаться» после;
- [ ] в обоих случаях: после обновления подтверждено, что все каналы
      поднялись (probe), зомби-первое-подключение погашено (CORE-01),
      алерт если какой-то юнит не поднялся.
