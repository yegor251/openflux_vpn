## Проблема

VPS-копия `users.json` (мастер ключей каналов, выпущенных ботом!) и
`bot_users.json` — единственные; случайная порча реестра / неудачный
rotate / человеческая ошибка = потеря всех ссылок пользователей.

## Модель (2026-10-23, решение админа)

**Ежедневный незашифрованный бэкап на самом VPS**, полностью
автоматически: `scripts/vps_backup.sh` + таймер
`oflux-backup.timer` (ежедневно 15:40 UTC, Persistent) →
`/root/backups/oflux-bot/oflux-bot-*.tar.gz`, 14 поколений, после
успеха обновляется штамп `.last-backup`, за которым следит watchdog
(алерт, если старше 36 ч).

**Принятый риск (записано осознанно):** бэкапы живут на том же VDS —
от полной гибели сервера они НЕ спасают. Закрывают: порчу реестра,
неудачный rotate, ошибочное удаление, сбой выпуска. Внешняя
(зашифрованная off-box) копия — сознательно отложена; заготовка
осталась в `scripts/backup_registry.sh` (pull/verify/drill).

## Ожидаемый результат

- [x] ежедневный автоматический бэкап реестра + bot_users + cookies +
      bot.yaml/servers.yaml (таймер, без участия админа);
- [x] восстановление отрепетировано: `backup_registry.sh drill vps`
      поднимает последний архив в scratch-каталоге и перевыпускает
      ссылки реальных каналов (4/4, 2026-10-23);
- [x] 14 поколений; контроль успешности — watchdog по штампу
      (алерт + напоминания + 🟢 при восстановлении свежести);
- [ ] раз в квартал повторить drill (напоминание — OPS-02).

## Как пользоваться

```
systemctl list-timers oflux-backup.timer   # расписание
ls /root/backups/oflux-bot/                # поколения
scripts/backup_registry.sh drill vps       # проверка восстановления (с мака)
```
