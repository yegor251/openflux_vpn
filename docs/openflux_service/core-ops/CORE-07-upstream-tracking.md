## Проблема

Апстрим движется очень быстро (node-v1.0.0 → v1.4.2 за три недели;
появились Telemost, striped-транспорты, JS-SDK). Мы принимаем
ядро ноды автоматически (таймер 6 ч, SHA-256 pin, rollback), а форк
инсталлятора (`deploy/make_fork.py`) громко падает при drift — но
**решение** «принимать/держать версию» сегодня принимается по факту,
а не по данным. Пример риска: #201 — релиз node-v1.6.0 без бинарников;
поведение нашего апдейтера на релизе с пустым списком ассетов не
проверялось. Ключевые для нас issues (#106, #193, #157, #83, #198)
отслеживаются вручную.

## Ожидаемый результат

- [ ] еженедельная автоматическая сводка (скрипт): новые node-v*/core
      релизы, diff CHANGELOG, состояние ключевых для нас issues —
      приходит админу (бот или текст для сессии агента);
- [ ] на каждую новую node-v*-версию — явное решение «принять/держать»
      с одной строкой обоснования в журнале сводок;
- [ ] апдейтер проверен на граничных случаях: релиз без ассетов,
      битый SHA-256, откат на предыдущую версию — ни один не оставляет
      ноду сломанной и ни один не молчит;
- [ ] наши три находки (зомби-первое-подключение, live-lock
      ренегоциации, RST-правило под ufw) оформлены в апстрим и имеют
      номера/ссылки здесь.
