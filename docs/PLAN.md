# План работ: multi-user VPN на OpenFlux (прод: direct; запасные проверены)

Цель: готовое решение «личный VPN для многих пользователей» без
бизнес-части. Каждый пользователь — свой канал: ключ + exit-инстанс на
VDS + openflux://-ссылка. Управление — CLI на машине администратора,
пользователи — Telegram-бот.

```
oflux-admin (наш код, Python)
   │ ключ + SSH node-install.sh + openflux://-ссылка
   ▼
VDS: systemd-каналы openflux-node@<user> (по одному активному клиенту)
   ▲
пользователь: openflux://-ссылка → готовое приложение (Desktop/Android/iOS)
```

Бэклоги: `docs/openflux_innersourse/` — апстрим (ядро, клиенты,
транспорты; 3 файла), `docs/openflux_service/` — наш сервис (бот, VPS,
эксплуатация; 5 файлов). Технические подробности библиотеки —
`src/docprovider/README.md` и исходники ядра.

## Транспорты: прод — носители (автомат на VPS)

С 2026-10-25/26 прод-каналы выпускаются **только на носителях** (решение
админа: IP VDS не чистый; см. память carrier-only-product, контекст —
`docs/WHY_MASKING.md`). Замеры и механика —
`docs/openflux_innersourse/transports/TR-10-new-transports-research-base.md`.

| транспорт | статус | goodput | автоматизация |
|---|---|---|---|
| **cupsonline** | прод №1 | 0.15–0.4 MB/s | `/issue`: сет из пула; пул пуст → бот сам минтит 8 комнат на VPS; отказ cups → фолбэк на telemost |
| **telemost** | прод №2 (фолбэк) | ~0.85 MB/s | бот создаёт конференцию сам (сессия админа на VPS); живёт ~24 ч без активности, продлевается использованием |
| direct | служебный | 2.5–3.7 MB/s | drill-прослушки/warm-up на нодах; в ссылки не входит |
| avito | мёртв | — | анти-абьюз ДЦ-IP; пере-тест только с куками браузера |
| yandex / mailru / vyandex | мертвы | — | #106/#193, sign-in; без внешнего события не возвращать |
| pruffme / mtslink / bitrix | не проверены | — | JS-пакеты; нужен клиент с вкладкой Transports |

**Автомат выпуска (v0.1.8+):** `/issue` → выбор носителя (пул → минт
комнат → telemost-фолбэк) → установка ноды → пин комнат → ссылка
(cups-only или telemost-only, адрес VDS в ссылку не входит). Rotate
сохраняет комнаты/конференцию. Doctor проверяет носитель по журналу ноды.

**Нюансы носителей:** cups троттлит СОЗДАНИЕ комнат по объёму (~40/день
с IP → 403 на часы; вход в комнаты не режется); telemost-конференция
живёт ~24 ч без активности и продлевается использованием; сессия
создания конференций (`telemost-session-cookies.txt`) обновляется
повторным логином в telemost + захватом запроса (TR-11).

**Незакрытые проверки:** долгой жизни cups-комнат (сутки+ — идёт),
поведение канала при смерти/истечении конференции telemost (пере-выпуск
руками), скорость в час пик.

  5+ каналов без ручного вмешательства» — перед ростом.

## Открытые вопросы

- Верхняя граница каналов на один VDS до деградации (l3 ест память на
  соединение) — измерить в нагрузочной проверке.
- DNS клиента через tun (UDP NAT в l3) — проверять живым tun-клиентом;
  socks5-стенды этот путь не трогают.
